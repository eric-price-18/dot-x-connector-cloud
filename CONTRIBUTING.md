# Contributing

Keep contributions small and include tests for changed behavior. Run the complete offline suite before opening a pull request.

Do not include personal/account information, production configuration, credentials, logs, database dumps or private signing material in an issue, patch or test fixture. Use explicitly synthetic data and reserved example domains.

Preserve default-deny gates, fixed destinations, owner/account binding, budget reservations and uncertain-outcome tombstones. Changes to authentication, keys, replies or spending controls need focused security review. Never turn live provider access on in CI.

Third-party code keeps its original license and notices. Keep generated-parser changes reproducible with the pinned generation script. New contributions to original project code are offered under the root MIT license unless separately identified and reviewed.
